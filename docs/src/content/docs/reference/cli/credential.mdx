---
title: archgate credential
description: "Git credential helper that supplies access tokens for Archgate plugin repositories."
---

Supplies git with a valid access token for Archgate plugin repositories. You do not normally run this command yourself -- git invokes it, and [`archgate login`](/reference/cli/login/) registers it for you.

```bash
archgate credential get
```

Plugin repositories are cloned over HTTPS from `plugins.archgate.dev`, and git authenticates those requests itself rather than going through the CLI. Access tokens are short-lived, so a token written once into your credential manager would stop working within the hour. This helper closes that gap: git asks it for credentials on each request, and it answers with a cached access token, renewing it from the stored refresh token only once it has lapsed.

The command speaks git's [credential helper protocol](https://git-scm.com/docs/git-credential) on standard input and output. It answers only for `plugins.archgate.dev` and stays silent for every other host, so credentials for the rest of your remotes keep using whatever helper you already configured.

## Subcommands

| Subcommand                  | Description                                              |
| --------------------------- | -------------------------------------------------------- |
| `archgate credential get`   | Print credentials for a plugin repository                |
| `archgate credential store` | Accept a credential from git (no-op)                     |
| `archgate credential erase` | Remove stored credentials when git reports them rejected |

`store` is deliberately a no-op: tokens come from `archgate login`, so there is nothing for git to teach the CLI.

## Configuration

`archgate login` writes the following to your global git config:

```ini
[credential "https://plugins.archgate.dev"]
	helper =
	helper = !archgate credential
```

The empty first entry resets any helper inherited from a broader config scope, so `archgate` is the only helper consulted for this host. `archgate login logout` removes both entries.

## Examples

Inspect what git receives:

```bash
printf 'protocol=https\nhost=plugins.archgate.dev\n\n' | archgate credential get
```

## Troubleshooting

### `git clone` prompts for a username and password

The helper is not registered. Run `archgate login` again, or check the configuration directly:

```bash
git config --get-all credential.https://plugins.archgate.dev.helper
```

The output should list an empty line followed by `!archgate credential`. If it does not, the CLI could not write your global git config -- confirm `git config --global --list` works.

### The helper is registered but credentials are still rejected

Confirm you are signed in with `archgate login status`. If the refresh token has expired or been revoked, `archgate credential get` cannot renew the access token and stays silent; `archgate login` re-establishes it.
