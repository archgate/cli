title: archgate credential
description: "Git credential helper som leverer tilgangstokener for Archgates plugin-repositorier."
---

Leverer git et gyldig tilgangstoken for Archgates plugin-repositorier. Du kjører normalt ikke denne kommandoen selv -- git kaller den, og [`archgate login`](/reference/cli/login/) registrerer den for deg.

```bash
archgate credential get
```

Plugin-repositorier klones over HTTPS fra `plugins.archgate.dev`, og git autentiserer disse forespørslene selv i stedet for å gå gjennom CLI-en. Tilgangstokener er kortlivede, så et token som skrives én gang til legitimasjonsbehandleren ville slutte å virke innen en time. Denne helperen tetter det hullet: git spør den om legitimasjon ved hver forespørsel, og den svarer med et mellomlagret tilgangstoken som først fornyes fra det lagrede refresh-tokenet når det har utløpt.

Kommandoen snakker gits [credential helper-protokoll](https://git-scm.com/docs/git-credential) over standard inn og ut. Den svarer bare for `plugins.archgate.dev` og er taus for alle andre verter, slik at legitimasjon for de øvrige remotene dine fortsetter å bruke den helperen du allerede har konfigurert.

## Underkommandoer

| Underkommando               | Beskrivelse                                                                  |
| --------------------------- | ---------------------------------------------------------------------------- |
| `archgate credential get`   | Skriver ut legitimasjon for et plugin-repositorium                           |
| `archgate credential store` | Tar imot legitimasjon fra git (no-op)                                        |
| `archgate credential erase` | Forkaster det mellomlagrede tilgangstokenet når git melder at det ble avvist |

`store` er bevisst en no-op: tokener kommer fra `archgate login`, så git har ingenting å lære CLI-en.

`erase` forkaster bare det mellomlagrede tilgangstokenet og beholder økten. Git sletter legitimasjon hver gang den blir avvist, og én enkelt 401 — et tilgangstoken som så vidt passerte fornyelsesvinduet, eller en forbigående feil fra plugins-verten — skal ikke koste deg en full innlogging. Neste forespørsel fornyer fra refresh-tokenet.

## Konfigurasjon

`archgate login` skriver følgende til den globale git-konfigurasjonen din:

```ini
[credential "https://plugins.archgate.dev"]
	helper =
	helper = !archgate credential
```

Den tomme første oppføringen nullstiller enhver helper som er arvet fra et bredere konfigurasjonsnivå, slik at `archgate` er den eneste helperen git spør for denne verten. `archgate login logout` fjerner begge oppføringene.

## Eksempler

Se hva git får tilbake:

```bash
printf 'protocol=https\nhost=plugins.archgate.dev\n\n' | archgate credential get
```

## Feilsøking

### `git clone` spør etter brukernavn og passord

Helperen er ikke registrert. Kjør `archgate login` på nytt, eller sjekk konfigurasjonen direkte:

```bash
git config --get-all credential.https://plugins.archgate.dev.helper
```

Utdataene skal vise en tom linje etterfulgt av `!archgate credential`. Hvis ikke, klarte ikke CLI-en å skrive den globale git-konfigurasjonen din -- bekreft at `git config --global --list` virker.

### Helperen er registrert, men legitimasjonen avvises fortsatt

Bekreft at du er logget inn med `archgate login status`. Hvis refresh-tokenet er utløpt eller tilbakekalt, returnerer helperen ingen legitimasjon og melder fra om feilen. Den leser bare tokensettet `archgate login` lagret, så tilbakefallet til eldre tokener som andre kommandoer har, gjelder ikke her. Kjør `archgate login` på nytt.
