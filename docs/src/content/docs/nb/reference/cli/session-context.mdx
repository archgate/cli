Les AI-editor-sesjonslogger for prosjektet. Nyttig for å revidere hva en AI-agent gjorde under en kodeøkt.

```bash
archgate session-context [subcommand] [options]
```

Uten underkommando leser den **gjeldende samtale** for editoren som kjører kommandoen, noe Archgate finner ut fra miljøet. To underkommandoer dekker resten: `list` for å oppdage tidligere sesjoner, og `show <session-id>` for å lese en bestemt en. Alle former skriver JSON til stdout, og bare sesjoner som hører til det gjeldende prosjektet, tas i betraktning.

## Valg

| Valg                | Beskrivelse                                                                                                                                     |
| ------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------- |
| `--editor <name>`   | Editor som skal leses: `antigravity`, `claude-code`, `codex`, `copilot`, `cursor`, `opencode` eller `pi`. Som standard den gjenkjente editoren. |
| `--max-entries <n>` | Høyeste antall oppføringer som returneres, nyeste først (standard: 200). Må være et positivt heltall.                                           |
| `--root`            | Kun opencode: løs opp en underagents barnesesjon til forelderen på øverste nivå. Avvises for alle andre editorer.                               |

## Underkommandoer

### archgate session-context list

List tilgjengelige sesjoner for prosjektet som JSON (`id`, `updatedAt`, og `title` for editorer som lagrer en), nyeste først. Godtar `--editor`.

```bash
archgate session-context list
```

### archgate session-context show

Les en bestemt sesjon etter ID (fra `list`). En eksplisitt ID vinner alltid over sesjonen som miljøet peker på. Godtar `--editor`, `--max-entries` og `--root`.

```bash
archgate session-context show <session-id>
```

## Editordeteksjon

Hver støttet editor merker prosessene den starter, og Archgate leser disse markørene for å finne ut hvilken editor som spør. Bruk `--editor` for å overstyre resultatet, eller for å lese sesjonsloggene til en annen editor.

Noen editorer publiserer også ID-en til samtalen de kjører akkurat nå. Når en gjør det, leser Archgate nettopp den samtalen i stedet for den nyeste. Dette betyr noe når et prosjekt har flere sesjoner åpne samtidig, der den nyeste kanskje ikke er samtalen du er en del av. En publisert ID som ikke passer til noen sesjon i prosjektet, blir ignorert, og den nyeste brukes i stedet — slik gjør en utdatert ID aldri en fungerende kommando om til en feil.

En publisert ID gjelder bare for editoren som publiserte den. Bruker du `--editor cursor` inne fra Claude Code, leses Cursors sesjonslogger etter nyeste.

Når markører fra mer enn én editor er til stede — en agent som kjører inne i en annen agent — avgjøres vinneren av en fast rekkefølge: `antigravity`, `claude-code`, `codex`, `copilot`, `cursor`, `pi`, og deretter `opencode`. Hvert treff rapporteres likevel i resultatet. Denne rekkefølgen gjelder uansett hvilke sesjons-ID-er som måtte være publisert: en tom eller ubrukelig ID endrer hvilken sesjon som velges, aldri hvilken editor.

Gjenkjenningen mislykkes når Archgate kjøres fra et vanlig skall i stedet for inne i en AI-editor. Kommandoen avslutter da med kode 1 og ber om `--editor`.

## Utdata

Hvert kall rapporterer hva det kom fram til i et `detection`-objekt ved siden av sesjonsdataene:

```json
{
  "detection": {
    "editor": "claude-code",
    "via": "CLAUDECODE",
    "session": "pinned",
    "candidates": ["claude-code"]
  },
  "sessionFile": "6ee6f0a5-1b2c-4d5e-8f90-a1b2c3d4e5f6.jsonl",
  "totalEntries": 182,
  "relevantEntries": 125,
  "transcript": []
}
```

| Felt                        | Betydning                                                                                                                                                                                               |
| --------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `detection.editor`          | Editor hvis sesjoner ble lest                                                                                                                                                                           |
| `detection.via`             | Miljøvariabelen som identifiserte editoren, eller `--editor` når du oppga en                                                                                                                            |
| `detection.session`         | `pinned` (editorens egen sesjons-ID ble brukt), `recent` (den nyeste sesjonen ble tatt), eller `explicit` (en ID ble oppgitt til `show`). Rapporteres ikke av `list`, som ikke velger én enkelt sesjon. |
| `detection.candidates`      | Hver editor hvis markør var til stede, i prioritert rekkefølge                                                                                                                                          |
| `sessionId` / `sessionFile` | Identifiserer sesjonen som ble lest; hvilken av de to som vises, avhenger av editoren                                                                                                                   |
| `totalEntries`              | Oppføringer i den lagrede sesjonen                                                                                                                                                                      |
| `relevantEntries`           | Samtaleoppføringer som gjenstår etter at bokføringshendelser og turer uten tekst er hoppet over                                                                                                         |
| `transcript`                | De siste `--max-entries` av disse oppføringene, hver med `role` og `contentPreview`                                                                                                                     |

`list` erstatter sesjonsdataene med en `sessions`-liste. Når ingen sesjon kan leses, skrives årsaken til stderr, og kommandoen avslutter med kode 1.

## Editorspesifikk oppførsel

- **Antigravity** og **Codex** har hver en CLI og en skrivebordsapp, og samtaler fra begge distribusjonene leses.
- **Codex** respekterer `CODEX_HOME`.
- **Pi** respekterer `PI_CODING_AGENT_DIR` og `PI_CODING_AGENT_SESSION_DIR`. Pi forgrener en sesjon i samme fil i stedet for å starte en ny, så bare den aktive grenen leses — en forgrenet eller tilbakerullet tur utelates. Pi publiserer sesjons-ID-en bare til kommandoer agenten selv kjører, så en kommando du skriver selv, gjenkjennes fortsatt som Pi, men velges etter nyeste.
- **opencode** registrerer underagent-kjøringer som barnesesjoner av samtalen som startet dem. Barnesesjoner holdes utenfor `list` og utenfor valget av nyeste, slik at den nyeste sesjonen på øverste nivå alltid er hovedøkten. De kan fortsatt leses etter ID med `show`, og `--root` løser opp en barnesesjon til forelderen på øverste nivå — nyttig når en underagent kjenner sin egen sesjons-ID og trenger samtalen den hører til.

## Eksempler

Les den gjeldende sesjonen, uansett hvilken editor som kjører:

```bash
archgate session-context
```

List sesjonene til den gjenkjente editoren:

```bash
archgate session-context list
```

Les den gjeldende sesjonen til en annen editor:

```bash
archgate session-context --editor opencode
```

Les en bestemt tidligere sesjon:

```bash
archgate session-context show 6ee6f0a5-1b2c-4d5e-8f90-a1b2c3d4e5f6
```

Løs opp en opencode-underagents barnesesjon til forelderen på øverste nivå:

```bash
archgate session-context show ses_child123 --editor opencode --root
```
