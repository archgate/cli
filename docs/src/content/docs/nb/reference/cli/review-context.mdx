Forhåndsberegn gjennomgangskontekst med ADR-briefinger for endrede filer. Designet for CI og editor-plugin-integrasjoner som trenger en oppsummering av hvilke ADR-er som gjelder for filene som endres.

```bash
archgate review-context [options]
```

## Valg

| Valg                | Beskrivelse                                                                                                                        |
| ------------------- | ---------------------------------------------------------------------------------------------------------------------------------- |
| `--staged`          | Inkluder kun git-stagede filer                                                                                                     |
| `--base [ref]`      | Sammenlign endrede filer mot en basisreferanse (autodetekteres hvis utelatt)                                                       |
| `--run-checks`      | Inkluder resultater fra ADR-samsvarskontroller                                                                                     |
| `--domain <domain>` | Filtrer til et enkelt domene                                                                                                       |
| `--verbose`         | Inkluder teksten for Decision og Do's/Don'ts fra hver ADR                                                                          |
| `--strict`          | Avslutt med kode 1 når sammendrag ble avkortet, eller (med `--run-checks`) når `check` fant funn som er relevante for streng modus |

## Eksempel

```bash
archgate review-context --staged
```

## Streng modus

Send `--strict` for å få denne kommandoen til å mislykkes (avslutningskode 1) i stedet for bare å rapportere: den mislykkes når `truncatedBriefings` ikke er tom (krever `--verbose` for at det skal være noe å avkorte), eller, med `--run-checks`, når den gjenbrukte `checkSummary.warningsExceeded` eller `checkSummary.strictAdvisoryExceeded` er `true`. `--strict` mislykkes **ikke** ved vanlige regelbrudd (`checkSummary.failed`/`ruleErrors`) — denne kommandoen forblir en kontekstgenerator for agenter, ikke en ny samsvarssperre; bruk [`archgate check`](/reference/cli/check/) for å sperre på regelbrudd. En `--strict`-feil skriver ut hele JSON-svaret først, og logger deretter årsaken til stderr før den avslutter.

`--strict` løses på samme måte som `archgate check --strict`: kommandolinjevalg, deretter en `strict: boolean`-nøkkel i `.archgate/config.json`, deretter av.

## Størrelse på utdata

Som standard identifiseres hver ADR bare med `id`, `title`, `domain`, `files` og `rules` — nok til å vite hvilke ADR-er som gjelder for de endrede filene. Les dem du trenger med `archgate adr show <id>`.

Bruk `--verbose` for å inkludere teksten for Decision og Do's/Don'ts fra hver aktuelle ADR i svaret. Denne teksten vokser med antallet ADR-er som treffer, og dominerer utdataene — i et repositorium med mange ADR-er blir den stor nok til at AI-agenter slutter å vise resultatet inline. Foretrekk standarden og hent detaljene ved behov; bruk `--verbose` bare når ett selvstendig svar er strengt nødvendig.

## Avkortede sammendrag

Sammendragsteksten har en øvre grense per seksjon. Når en Decision- eller Do's and Don'ts-seksjon overskrider grensen, blir den kuttet, og utelatelsen rapporteres på fire måter:

- Kuttpunktet markeres i teksten med `[... truncated — read full ADR via adr://<id>]`.
- ADR-ens eget sammendrag lister de berørte seksjonsnavnene i `truncatedSections`.
- Alle berørte ADR-id-er samles i `truncatedBriefings` på øverste nivå. Listen fylles etter `--domain`-filtrering, så den navngir bare ADR-er som finnes i svaret.
- En advarsel som navngir disse ADR-ene skrives til stderr, slik at stdout forblir gyldig JSON.

Tolk alle disse signalene som at ADR-ens styrende tekst er ufullstendig: reglene den fastsetter kan ligge i den delen som ble kuttet. Les hele dokumentet med `archgate adr show <id>` før du stoler på sammendraget.

To andre grenser avkorter dette svaret, hver med sin egen advarsel til stderr. `truncatedFiles` settes når listen over endrede filer overskrider grensen sin, slik at filer utover den mangler i alle domener. Med `--run-checks` settes `checkSummary.truncated` når en regel rapporterte flere brudd enn grensen per regel — kjør [`archgate check`](/reference/cli/check/) for den fullstendige listen.

Når `--run-checks` brukes, følger `checkSummary` samme regel som [`archgate check --output json`](/reference/cli/check/): `results`-listen inneholder bare regler som har noe å rapportere, mens tellerne ved siden av fortsatt dekker alle reglene som ble kjørt.
