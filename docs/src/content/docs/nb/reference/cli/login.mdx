Logg inn på Archgate-plattformen. Innloggingen er det som gir tilgang til editor-pluginene.

```bash
archgate login
```

Starter en OAuth 2.0 Device Authorization Grant (RFC 8628) mot Archgate-plattformen. CLI-en åpner nettleseren på en URL som allerede inneholder engangskoden, og kopierer koden til utklippstavlen i tilfelle siden spør etter den. Både URL-en og koden skrives også ut, så du kan fullføre på en annen maskin eller lime dem inn selv.

Ingen av delene er påkrevd. I CI, over SSH eller på en ren Linux-maskin uten skjermserver (WSL når Windows-skrivebordet) hopper CLI-en over begge og skriver dem bare ut. Når autorisasjonen er fullført, gir CLI-en tokenene til git via `git credential approve`, så hvor de havner avhenger av hvilken credential-helper du har konfigurert. En helper som bruker operativsystemets legitimasjonsbehandler (macOS Keychain, Windows Credential Manager, Linux libsecret) holder dem krypterte; gits innebygde `store`-helper skriver dem til `~/.git-credentials` i klartekst. Sjekk din med `git config --global credential.helper`.

Tilgangstokener er kortlivede. CLI-en beholder et refresh-token ved siden av dem og fornyer tilgangstokenet automatisk, så det holder normalt å logge inn én gang. Hvis selve refresh-tokenet utløper eller blir tilbakekalt, melder CLI-en at økten er utløpt, og `archgate login` gjenoppretter den. Et token utstedt før denne flyten fantes virker bare til du logger inn på plattformen; fra da av er det plattformøkten alene som gjelder.

Innlogging registrerer også `archgate credential` som en git credential helper for `plugins.archgate.dev`, som er det som lar `git clone` av et plugin-repositorium autentisere uten å spørre. Se [`archgate credential`](/reference/cli/credential/).

Legitimasjon kreves for å installere editor-plugins via `archgate init --install-plugin`. Selve CLI-en (check, init osv.) fungerer uten innlogging.

:::tip[Plugin-beta]
Editor-plugins er for tiden i beta. Kjør `archgate login` for å logge inn.
:::

## Underkommandoer

| Underkommando            | Beskrivelse                                      |
| ------------------------ | ------------------------------------------------ |
| `archgate login`         | Autentiser (hopper over hvis allerede innlogget) |
| `archgate login status`  | Vis gjeldende autentiseringsstatus               |
| `archgate login logout`  | Fjern lagret legitimasjon                        |
| `archgate login refresh` | Logg inn på nytt og erstatt lagrede token        |

## Eksempler

Logg inn for første gang:

```bash
archgate login
```

```
By signing in, you agree to the Archgate Terms of Service:
https://archgate.dev/terms-of-service

Opened https://auth.archgate.dev/device?user_code=HZML-HXLB in your browser.
If it asks for a code, enter: HZML-HXLB (copied to your clipboard)

Waiting for authorization...
info: Authenticated as yourname. Plugin access is now available.
Run `archgate init` to set up a project with the archgate plugin.
```

Hvis prosjektet allerede har `.archgate/adrs/`, lyder den siste linjen:

```
Run `archgate check` to validate your project against its ADRs.
```

## Feilsøking

### TLS/bedriftsproxy-feil

Hvis `archgate login` feiler med en TLS-sertifikatfeil (vanlig bak bedriftsproxyer), pek kjøretidsmiljøet mot organisasjonens CA-sertifikatpakke ved å bruke miljøvariabelen `NODE_EXTRA_CA_CERTS`.

På macOS/Linux:

```bash
export NODE_EXTRA_CA_CERTS=/path/to/your-corporate-ca.pem
archgate login
```

På Windows (PowerShell):

```powershell
$env:NODE_EXTRA_CA_CERTS = "C:\path\to\your-corporate-ca.pem"
archgate login
```

På Windows (cmd):

```cmd
set NODE_EXTRA_CA_CERTS=C:\path\to\your-corporate-ca.pem
archgate login
```

På Windows (Git Bash):

```bash
export NODE_EXTRA_CA_CERTS=/c/path/to/your-corporate-ca.pem
archgate login
```

Spør IT-avdelingen din om riktig sertifikatsti hvis du er usikker.

Sjekk innloggingsstatus:

```bash
archgate login status
```

```
Logged in as yourname.
```

Logg ut:

```bash
archgate login logout
```

Autentiser på nytt:

```bash
archgate login refresh
```
