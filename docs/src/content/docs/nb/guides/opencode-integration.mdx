Archgate integreres med [opencode](https://opencode.ai) for å gi AI-agenter innebygde guardrails. Agenten leser ADR-ene dine før den skriver kode, validerer etterpå, og fanger opp nye mønstre for teamet -- den samme arbeidsflyten som er tilgjengelig i [Claude Code-pluginet](/guides/claude-code-plugin/).

## Oppsett

Kjør `archgate init` med `--editor opencode`-flagget for å konfigurere opencode-integrasjon i prosjektet ditt:

```bash
archgate init --editor opencode
```

:::note[Betatilgang kreves]
opencode-agentpakken er for øyeblikket i beta. Kjør `archgate login` for å registrere deg og autentisere.
:::

opencode-agentene og -ferdighetene skrives **ikke til prosjekttreet ditt** -- i motsetning til Cursor, som også installerer sine agenter og ferdigheter på brukernivå, men likevel skriver `afterFileEdit`-hooken sin i prosjektets `.cursor/hooks.json`. For opencode havner ingenting editorspesifikt i repositoriet: alt bor på maskinen din og er tilgjengelig på tvers av alle prosjekter du åpner med opencode.

opencode bruker XDG Base Directory-konvensjonen på alle plattformer (via `xdg-basedir`-pakken), så installasjonsplasseringen løses opp til `$XDG_CONFIG_HOME/opencode/` når den variabelen er satt, og faller tilbake til `$HOME/.config/opencode/` ellers. Det betyr at Windows-installasjoner havner under `C:\Users\<brukernavn>\.config\opencode\`, ikke under `%APPDATA%`:

| Plattform     | Installasjonsplassering                                                 |
| ------------- | ----------------------------------------------------------------------- |
| Linux / macOS | `$XDG_CONFIG_HOME/opencode/`, med tilbakefall til `~/.config/opencode/` |
| Windows       | `C:\Users\<brukernavn>\.config\opencode\` (samme tilbakefallsregel)     |

Inne i den katalogen skrives agenter til `agents/` og ferdigheter til `skills/`.

### Autentisert installasjon

:::caution[opencode må være installert først]
Installasjonstrinnet kjører bare når Archgate kan se opencode på maskinen din -- enten `opencode`-CLI-en på PATH, eller opencode-konfigurasjonskatalogen (`~/.config/opencode/`), som Desktop-appen også bruker selv om den ikke leverer noen CLI-binærfil. Archgate trenger den bekreftelsen før den skriver filer til brukernivåets konfigurasjonskatalog -- ellers ville pakken ligge på en plassering ingenting leser. Installer opencode fra [opencode.ai](https://opencode.ai/docs/) først, og kjør deretter `archgate init --editor opencode` eller `archgate plugin install --editor opencode` på nytt.
:::

Hvis du har logget inn via `archgate login` **og** opencode er oppdaget, laster init-kommandoen ned og installerer Archgate-pakken for opencode. Pakken tilbyr to ferdigbygde primæragenter og fem ferdigheter som gir opencode sin AI en komplett guardrails-arbeidsflyt.

For å eksplisitt installere pakken:

```bash
archgate login                                  # engangsoppsett
archgate init --editor opencode --install-plugin
```

For å installere eller reinstallere på et allerede initialisert prosjekt:

```bash
archgate plugin install --editor opencode
```

Installasjonstrinnet laster ned en autentisert tarball fra Archgate plugins-tjenesten og pakker ut `agents/`- og `skills/`-katalogene i opencode brukernivå-katalogen. Eventuelle `archgate-*`-agentfiler og `archgate-*/`-ferdighetskataloger fra en tidligere installasjon fjernes først, så det å kjøre kommandoen på nytt erstatter pakken i stedet for å legge seg oppå den. Filer som ikke ligger under `agents/` eller `skills/` ignoreres, så ingenting annet i opencode-konfigurasjonskatalogen din berøres.

### Genererte filer (brukernivå)

| Fil                                                          | Formål                                                                                         |
| ------------------------------------------------------------ | ---------------------------------------------------------------------------------------------- |
| `<opencode-config>/agents/archgate-developer.md`             | Primær agent som kjører den fulle ADR-arbeidsflyten                                            |
| `<opencode-config>/agents/archgate-planner.md`               | Skrivebeskyttet primær agent som utformer ADR-samsvarende implementeringsplaner                |
| `<opencode-config>/skills/archgate-reviewer/SKILL.md`        | Validerer kodeendringer mot alle prosjektets ADR-er                                            |
| `<opencode-config>/skills/archgate-lessons-learned/SKILL.md` | Fanger opp læringer og foreslår nye ADR-er                                                     |
| `<opencode-config>/skills/archgate-adr-author/SKILL.md`      | Oppretter og redigerer ADR-er i henhold til prosjektets konvensjoner                           |
| `<opencode-config>/skills/archgate-cli-reference/SKILL.md`   | Intern referanse med Archgate CLI-kommandoguiden                                               |
| `<opencode-config>/skills/archgate-onboard/SKILL.md`         | Engangsoppsett: utforsker kodebasen, intervjuer deg, oppretter innledende ADR-er               |
| `<opencode-config>/opencode.json`                            | Brukerinnstillinger -- `default_agent` settes til `archgate-developer` hvis ikke allerede satt |

`opencode.json`-sammenslåingen er additiv og overskriver aldri en eksisterende `default_agent`, så ditt eget valg av standardagent bevares.

`.archgate/adrs/` og `.archgate/lint/` opprettes fortsatt i prosjektet som vanlig. Bare de opencode-spesifikke filene bor utenfor prosjekttreet.

## Hva pakken tilbyr

`archgate-`-prefikset unngår kollisjoner med brukeropprettede opencode-agenter eller -ferdigheter i de samme katalogene. Ferdigheter aktiveres via opencodes `@-mention`-syntaks.

### Primæragenter

| Navn                 | Formål                                                                                  |
| -------------------- | --------------------------------------------------------------------------------------- |
| `archgate-developer` | Generell utviklingsagent som leser ADR-er før koding og validerer etterpå               |
| `archgate-planner`   | Skrivebeskyttet planleggingsagent som utformer ADR-samsvarende planer uten å endre kode |

`archgate-developer`-agenten orkestrerer ferdighetene nedenfor automatisk som en del av arbeidsflyten. Begge agentene er opencode-_primæragenter_, så du bytter mellom dem med Tab-tasten.

### Ferdigheter

| Navn                       | Formål                                                                                  |
| -------------------------- | --------------------------------------------------------------------------------------- |
| `archgate-reviewer`        | Validerer kodeendringer mot alle prosjektets ADR-er for strukturell samsvar             |
| `archgate-lessons-learned` | Gjennomgår regeldekning og foreslår nye ADR-er når mønstre dukker opp                   |
| `archgate-adr-author`      | Oppretter og redigerer ADR-er i henhold til prosjektets konvensjoner                    |
| `archgate-cli-reference`   | Intern referanse for AI-agenter med den komplette Archgate CLI-kommandoguiden           |
| `archgate-onboard`         | Engangsoppsett: utforsker kodebasen, intervjuer utvikleren, oppretter innledende ADR-er |

Disse er de samme rollene som er tilgjengelige i Claude Code-pluginet, tilpasset opencodes opprinnelige agent- og ferdighetsmodell.

## Hvordan det fungerer i praksis

Installasjonen setter `archgate-developer` som opencodes `default_agent` når du ikke allerede har valgt en, så den er som regel forhåndsvalgt for deg; ellers bytter du til den med Tab-tasten når du starter en kodeoppgave. Agenten følger en strukturert arbeidsflyt for hver endring:

1. **Les gjeldende ADR-er** -- Agenten kjører `archgate review-context` for å se hvilke ADR-er som gjelder for filene som endres. Den skriver ikke kode før den har lest de gjeldende ADR-ene.

2. **Skriv kode i henhold til ADR-begrensninger** -- Agenten implementerer endringer i henhold til Do's and Don'ts fra de gjeldende ADR-ene.

3. **Kjør samsvarssjekker** -- Agenten kjører `archgate check` for å utføre automatiserte regler. Eventuelle brudd utbedres før man går videre.

4. **Reviewer-validering** -- Agenten nevner `@archgate-reviewer` for å validere strukturelt ADR-samsvar utover det automatiserte regler fanger opp.

5. **Fang opp læringer** -- Agenten nevner `@archgate-lessons-learned` for å gjennomgå arbeidet og identifisere mønstre som er verdt å fange opp som nye ADR-er eller oppdateringer til eksisterende.

## ADR-drevet avvisning

Når `archgate-developer` møter en oppgave som ville kreve brudd på en ADR, avviser den og forklarer hvilken ADR som ville bli brutt. Den foreslår deretter hvordan man kan oppnå det samme målet uten å bryte reglene.

Hvis for eksempel en utvikler ber agenten om å legge til `chalk` som en avhengighet i et prosjekt styrt av en ADR for avhengighetspolicy, vil agenten:

1. Avvise, med henvisning til ADR-en og den godkjente avhengighetslisten
2. Foreslå det godkjente alternativet i stedet
3. Tilby å implementere oppgaven med den samsvarende tilnærmingen

Denne oppførselen er konsistent uavhengig av hvordan utvikleren formulerer forespørselen. ADR-er behandles som obligatoriske begrensninger, ikke forslag.

## Når du skal bruke hver agent eller ferdighet

| Scenario                                          | Agent / Ferdighet             |
| ------------------------------------------------- | ----------------------------- |
| Daglige kodeoppgaver                              | `archgate-developer` (primær) |
| Planlegge en endring uten å skrive kode           | `archgate-planner` (primær)   |
| Sette opp Archgate i et prosjekt for første gang  | `@archgate-onboard`           |
| Gjennomgå en endring for ADR-samsvar              | `@archgate-reviewer`          |
| Oppdage et gjentagende mønster verdt å kodifisere | `@archgate-lessons-learned`   |
| Opprette eller redigere en ADR                    | `@archgate-adr-author`        |

`archgate-developer`-agenten orkestrerer ferdighetene automatisk -- den nevner `@archgate-reviewer` og `@archgate-lessons-learned` som en del av arbeidsflyten. Mesteparten av tiden trenger du bare å velge `archgate-developer` og la den kjøre.

## Brukernivå vs. prosjektnivå

opencode-pakken bor i opencode-katalogen på brukernivå i stedet for i `.opencode/` inne i prosjektet ditt. Konsekvenser:

- **En installasjon per maskin.** `archgate plugin install --editor opencode` installerer pakken globalt. Alle prosjekter du åpner med opencode ser de samme `archgate-*`-agentene og -ferdighetene.
- **Repositoriet ditt forblir rent.** Ingen `.opencode/`-mappe opprettes noensinne av `archgate init`. Teammedlemmer som ønsker agentene kjører sin egen `archgate plugin install --editor opencode`.
- **Oppgraderinger er globale.** Å kjøre `archgate plugin install --editor opencode` på nytt fjerner de forrige `archgate-*`-agentene og -ferdighetene og erstatter dem med den nyeste pakken.

## Tips for effektiv bruk

- **Kjør `@archgate-onboard` én gang per prosjekt** for å generere de innledende ADR-ene dine fra den faktiske kodebasen.
- **Velg `archgate-developer` ved starten av kodeøkter.** Den orkestrerer hele les-valider-fang-opp-arbeidsflyten automatisk.
- **Bruk `@archgate-reviewer` for gjennomganger.** Den validerer strukturelt samsvar utover det automatiserte regler fanger opp.
- **Bruk `@archgate-lessons-learned` etter å ha løst vanskelige problemer.** Den fanger opp læringer slik at de samme feilene ikke gjentas.
- **Hold ADR-regelfiler oppdatert.** Agenten håndterer det reglene sjekker for -- hvis en regel mangler, vil bruddet ikke bli fanget opp.
- **Kjør `archgate plugin install --editor opencode` på nytt for å oppgradere.** Tjenesten returnerer den nyeste agentpakken ved hver autentisert nedlasting.
