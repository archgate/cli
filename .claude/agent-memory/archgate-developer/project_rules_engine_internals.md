## Scanner and AST internals

- **A node rejected by `AstNodeSchema.safeParse` is dropped WITH its whole subtree, so an over-strict schema is a silent security false-negative** — a banned global nested inside a rejected node goes unscanned and `check` reports pass (ARCH-024 clause 7). `type` is always present and typed children recurse, so a `Literal`'s `value` is the only leaf that can independently fail — keep it `z.unknown().optional()`. Fired twice: null `source` on `export`-without-`from` (#493) and exotic `value` — meriyah emits `{}` for a RegExp literal and a `bigint` for `123n` (#494). Always fix by WIDENING the schema, never by adding a new check. Zod v4 gotcha: bare `z.unknown()` is NON-optional.
- **`Bun.Transpiler` normalizes computed access to dotted form before the scanner's AST sees it**: `obj["x"]`→`obj.x`, `import.meta["require"]`→`import.meta.require`. So (1) the AST's `computed` flag does NOT reflect the original spelling — use `staticPropName(prop, computed)` in `src/engine/rule-scanner.ts`, not `prop.name` + `!computed`; and (2) `remapViolations` searches the UNTRANSPILED source, so an anchor taken from the normalized spelling won't be found and remaps to line 0 — anchor on a substring common to both spellings (e.g. `import.meta`).
- **The AST-walk occurrence counter and `source-positions.findCodeOccurrences` must count the same set.** `remapViolations` finds the Nth code-position occurrence of `searchText`, skipping strings/comments but NOT property keys — so when the walk skips EMITTING for a position (a banned global in a key slot, `{ Bun: 1 }`), it must still ADVANCE the counter, or a later real reference remaps onto the skipped key. `checkBannedIdentifier` does count-without-emit for this reason. Residual: `findCodeOccurrences` is substring-based, so `Bun` inside `Bundle` is miscounted.
- **`Bun.Transpiler` strips provably-dead code before the scanner sees it — correct, not a gap.** `const y = /x/ || import("node:child_process")` becomes `const y = /x/;`. When writing an escape regression test, put the payload in a REACHABLE position and confirm `transformSync` keeps it, or the test passes for the wrong reason.
- **`ctx.ast()` results are cached per `check` run for every language**, keyed on path+language+`rev`+`comments` (`astCacheKey`), and the PROMISE is cached so rejections stick. A file rewritten mid-run therefore re-parses to the ORIGINAL bytes — don't write tests that rewrite a file mid-`check` to prove change detection; use two committed states or the base-vs-head comparison.
- **Editing `ctx.ast()` / `RuleContext` trips three of ARCH-022's own rules.** (1) `single-ast-method` matches ONE exact `ast(...)` catch-all line by literal regex in BOTH `src/formats/rules.ts` and `src/helpers/rules-shim.ts` (a hand-maintained mirror — sync every field). The catch-all must carry the same `opts?: AstOptions` the literal overloads carry, or a caller holding a dynamically-typed `AstLanguage` silently loses every option. When you change that signature, update the rule's regex and message in the SAME change (via the `adr-author` skill) and fire-test both directions. (2) `ast-guardrail-ordering` requires the markers `safePath`, `AST_LANGUAGE_EXTENSIONS`, `probeInterpreter`, `runAstSubprocess` to appear textually in order INSIDE `ast()` in `runner.ts` — you cannot extract those past guardrails into a helper. (3) `runner.ts` rides the 500-line oxlint `max-lines` cap, so buy space by extracting what holds NO marker: error-message builders and temp-file helpers to `ast-support.ts`, base-revision git reads to `git-files.ts`, line-scanning to `glob-utils.matchLines`.

- **`realpath` comparisons must be realpath-against-realpath, never realpath-against-lexical.** `realpathSync` case-canonicalizes on Windows and macOS, so comparing its output against a lexically-built path rejects case-mismatched-but-legitimate paths. Resolve both sides — see `realRootOf` in `src/engine/safe-path.ts`. This is why the first version of the symlink walk deliberately used boolean `lstat` instead.

## Authoring rules and commands

- **Pending: the `.rules.ts` load phase re-transpiles and meriyah-parses every rules file per invocation** (~700ms incl. Bun startup on a large project). Plan: content-hash cache under `~/.archgate/`. User approved deferring this (2026-07-13); the per-run caches in `runner.ts` do NOT cover it.
- **When authoring or changing a `.rules.ts` rule, verify BOTH directions.** (1) Dogfood: run `bun run cli check --adr <ID>` on the repo and expect a false-positive triage round — the ARCH-012 coverage rule flagged 9 legitimate `await exitWith(...)` guards (→ exemption list) and caught 1 real bug. (2) Fire test: drop a throwaway bad-pattern file, confirm the rule warns with the right line, then delete it — silence on a clean repo proves nothing. Re-run both after refactoring the rule.
- **Commit BEFORE fire-testing a rule or guard.** The fire-test loop (mutate a file → confirm the check fails → restore) restores with `git checkout <file>`, which discards ALL uncommitted work in that file — including the fix being tested. Cost a full re-apply of the safePath fix on 2026-07-25. Either commit first, or restore from an explicit `cp` backup rather than git.
- **The repo's own regex-based ADR rules match banned literals inside your `src/` CODE COMMENTS.** ARCH-014 greps for the Node environment accessor and ARCH-007 for its banned spawn APIs — they scan source text, not the AST, so a comment quoting the literal fails `archgate check`. Reword the comment to avoid it. Bites hardest when editing engine/security code that necessarily discusses banned patterns.
- **Commander hoists parent-known options away from nested subcommands.** If parent and child both declare `--max-entries`, commander parses it onto the PARENT regardless of argv position and the child's `opts` gets `undefined`. Read merged values via `command.optsWithGlobals()` (third action param) and regression-test through the full `parseAsync` path (broke in v0.46.0, fixed in #448).
- **To share I/O between commands, export from the command file that already defines it — don't create a new shared file.** ARCH-002 forbids `console.log` in helpers, and ARCH-001/ARCH-016 require a `register*Command` export plus a docs heading for any new command file. Pattern: `plugin/install.ts` exports `installForEditor()`/`printManualInstructions()`, imported by `upgrade.ts`.

- **Fire-test a guard in BOTH directions: that it blocks the bad case AND still permits the legitimate one.** Proving a guard is load-bearing (stub it out → test fails) only shows the gate closes; it says nothing about over-rejection. 2026-07-25: the ARCH-024 ancestor-symlink guard (#499) passed a green suite while rejecting _every_ symlinked component below the project root, including links pointing back INSIDE the project — which breaks workspace monorepos (pnpm/npm/yarn/bun symlink `node_modules/<pkg>` → `packages/<pkg>`) and symlinked shared source dirs. It reached main before the false positive was caught; fixed in #500 by gating on the link's resolved TARGET rather than its existence. For any boundary check, write the allow-case test alongside the deny-case one.
- **When testing an "empty X" case, test the degenerate form, not a near-empty variant.** A test named "returns {} for an empty frontmatter block" used `---\n\n---` — a blank line the body group can capture — and passed, hiding that the truly empty `---\n---` did not match at all. The near-miss variant exercises a different path than the one the test name claims.
- **Never chain cleanup of a temp script with `&&`, and never `git add -A` after using one.** `python fix.py && rm -f fix.py` leaves the script behind whenever it exits non-zero — exactly when a failed edit makes cleanup most necessary — and a later `git add -A` commits it. A throwaway `fix-sec-test.py` reached PR #500 this way (2026-07-25) and the maintainer caught it in review; nothing in `validate` flags a stray root-level `.py` (not linted, not in `src/`, invisible to knip). Use `; rm -f` or a `trap`, prefer `git add <explicit paths>`, and check `git diff --name-only origin/main...HEAD | grep -v /` before pushing.

## Reviewing

- **Verify a reviewer sub-agent's claim against the source before acting — it misquotes both ADRs and the files it just read.** A haiku agent flagged "await on a synchronous helper" as an ARCH-012 violation when ARCH-012 only mandates try-catch boundaries and exit codes; another returned FAIL on a Norwegian doc claiming it read "gjeta" when the file already said "gjenta", so applying the fix would have INTRODUCED the error. Re-read the cited ADR's Decision/Do's, and `grep` the exact quoted string, before accepting a FAIL. Highest risk on non-English prose the agent can't sanity-check by meaning. A finding citing no ADR (self-labeled "ARCH-NONE") can never block.
